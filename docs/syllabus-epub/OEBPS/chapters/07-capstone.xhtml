Session 7: Chaining It Together

Goal for this session: nothing new to learn. Every step below was covered in an earlier session. The point is to start cold, the way a real engagement starts, run three chains end to end in one sitting, and then write the whole thing up as if a client were paying for it. A finding on its own is a line in a report. A chain is the reason the client keeps you on the phone.

Two services, each with a finding a scanner would rate "medium," combine into code execution on the web host. Neither ZAP nor an FTP scan, run alone, would have connected them.

7.5 The Write-Up

Now produce the deliverable. For each chain:

  • Narrative. What an attacker does, in order, in plain sentences. No tool output yet.
  • Evidence. The exact requests and responses, trimmed to what proves the point.
  • Impact. What the attacker can now do that they could not before. Be specific: "read any customer's order," "execute commands as the web user," not "high severity."
  • Remediation. The fix for each link, and which single fix breaks the whole chain if you can only ship one this quarter.

Cross-check your findings against docs/scenarios.md, the instructor edition. If you found all twenty-four and can defend the fix for each, you have completed the course. If ZAP found ten and you found the other fourteen with your own head, you have understood it.

7.6 Closing the Loop

The tools in this course each do one job well. ZAP sweeps. sqlmap drills. testssl.sh reads a handshake. gobuster guesses paths. Wireshark shows you the wire. None of them chains findings, weighs impact, or writes the sentence that makes a client act. That part was never going to be the tool's job, and it isn't. What stays constant across every engagement is the tester's job: sweep with the tool, go where the tool stops, connect the small things into the big thing, and hand back a report someone can act on. That is the whole course in one sentence. Let the scanner sweep, then think.
