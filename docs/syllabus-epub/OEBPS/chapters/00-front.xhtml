Widgetorium 101

A Hands-On Training Syllabus for the Widgetorium Web Pen Testing Lab

By Britley Hoff

2026 Edition

Nobody hands you a live target on day one. You do not get to point a scanner at a production storefront and see what falls out, and you should not want to. That is the gap this syllabus fills: a deliberately broken web application, a misconfigured file server, and a database full of fake customers, all running on your own machine with nothing routable anywhere near it.

This is a six session course built entirely on the Widgetorium lab. Widgetorium is a dull beige widget shop, brackets and bolts and cable tidies, with nineteen planted weaknesses across SQL injection, transport security, the general web application layer, and an old FTP box wired into the same network. Every payload and every command in this book was run against the actual containers before this book went to print, not described from memory. Where the lab has an edge, the base image ships an OpenSSL without RC4 so you cannot demonstrate that particular cipher, vsftpd's anonymous path segfaults about once in a few hundred hits under a machine-gun scanner, this book says so plainly instead of pretending otherwise. A training environment that is honest about its own edges is more useful than one that quietly hopes you will not notice them.

The teaching flow is ZAP first. OWASP ZAP does the discovery sweep for each category, and a purpose-built spot-check tool confirms or exploits whatever ZAP surfaces: sqlmap for the injection points, testssl.sh for the certificate and cipher findings, gobuster for the content it missed, Wireshark for the FTP capture. Several of the nineteen, ZAP will not find on its own. That is not a bug in ZAP. A scanner connects a request to a response; it does not reason about who owns an order, whether a stored value will be trusted later, or what a session token is made of. Learning where the tool stops is half the point of the course.

By the end you will have dumped the customer table through a search box, walked into the admin panel two different ways, planted a payload that fires only when an administrator opens a report, read a file off the database host through a price field, pulled a live API key out of an exposed .git directory, uploaded a web shell through an anonymous FTP login and run it from a browser, and chained the small findings into the big one. Then you will write it up.

Standing Up the Lab

Widgetorium is one docker-compose stack: a PHP and Apache storefront, a seeded MySQL 8 backend that is never published to the host, and an intentionally misconfigured vsftpd whose anonymous upload directory is shared straight into the web root. Every published port binds to 127.0.0.1 only.

cd widgetorium
./setup.sh          # preflight, build images, generate the lab certs, plant the .git history
./start.sh          # bring it up; refuses to launch if any port would bind beyond loopback
./status.sh         # health check plus a loopback bind audit
./reset.sh          # wipe stateful bugs back to seed between cohorts

Each session assumes a fresh browser session and a clean cookie jar. There is no shared state between sessions except what you plant yourself: an injected product row, a stored review, an uploaded shell. Run ./reset.sh when you want the lab back to seed.

The Toolbox

You do not need all of these on day one. ZAP and curl get you through Session 1. The rest come in where the syllabus calls for them.

ToolRole in this course
OWASP ZAPPrimary discovery. Spider, AJAX spider, passive and active scan, and the Automation Framework plan shipped in docs/zap/.
sqlmapConfirms and exploits every SQL injection point, including the second-order one. Teaches what --level and --risk actually change.
testssl.shCertificate and TLS findings in one readable report: protocol versions, cipher strength, DH size, expiry, hostname mismatch, missing HSTS. sslyze is the alternative.
gobuster / ffufContent and directory discovery. Finds the exposed /admin/.git/ and the path an FTP-uploaded shell landed on.
git-dumperReconstructs the exposed .git repository and its history so you can recover the secret from an old commit.
Burp Suite CommunityRepeater and Intruder for manual request tampering: the IDOR walk, the upload filename, the API body. Worth teaching because trainees will meet it in the field.
curl / httpieManual request crafting before anyone reaches for a tool. The auth bypass, the IDOR, and the API endpoint are all one-liners.
nmapService and version detection, mainly against the FTP box (-sV -sC -p21).
NiktoFast web-server misconfiguration sweep, a cross-check against ZAP's active scan.
Wireshark / tcpdumpCapture the cleartext FTP login on the loopback interface.
hydraCredential brute-forcing against the FTP service account, the ftpuser:ftpuser teaching moment.
John the Ripper / hashcatCrack the unsalted MD5 password hashes pulled from the users table.
Python + requestsAbout twenty lines to demonstrate predictable session-token prediction. Not a tool problem, a scripting one.
MetasploitOptional. A module-driven exploit path against the FTP box, for contrast with doing it by hand.
Browser dev toolsInspect the session cookie, craft and confirm XSS payloads, watch the downgrade.

The instructor edition of the scenario guide, docs/scenarios.md in the lab repo, maps every one of the nineteen findings to the tool that confirms it and the fix that closes it. Trainees work from docs/scenarios-trainee.md, the same document with the fix removed.
