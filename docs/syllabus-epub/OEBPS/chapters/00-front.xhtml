Widgetorium 101

A Hands-On Training Syllabus for the Widgetorium Web Pen Testing Lab

By Britley Hoff

2026 Edition

Nobody hands you a live target on day one. You do not get to point a scanner at a production storefront and see what falls out, and you should not want to. That is the gap this syllabus fills: a deliberately broken web application, a misconfigured file server, and a database full of fake customers, all running on your own machine with nothing routable anywhere near it.

This is a six session course built entirely on the Widgetorium lab. Widgetorium is a widget shop, brackets and bolts and cable tidies, dressed up like a cross between a chocolate factory and a mail-order novelty catalogue, with nineteen planted weaknesses across SQL injection, transport security, the general web application layer, and an old FTP box wired into the same network. Every payload and every command in this book was run against the actual containers before this book went to print, not described from memory. Where the lab has an edge, the base image ships an OpenSSL without RC4 so you cannot demonstrate that particular cipher, vsftpd's anonymous path segfaults about once in a few hundred hits under a machine-gun scanner, this book says so plainly instead of pretending otherwise. A training environment that is honest about its own edges is more useful than one that quietly hopes you will not notice them.

The teaching flow is old-school first. Every session starts with the finding worked by hand, a browser, curl, openssl, a packet capture, a short script, and only then brings in a scanner to confirm it and cover ground faster. OWASP ZAP is the discovery sweep once you already know the app; sqlmap enumerates an injection point you have already exploited by hand; testssl.sh prints the report whose lines you can already read out of a raw handshake. Doing it the manual way first is not nostalgia. Several of the nineteen findings no scanner will surface on its own, a scanner connects a request to a response, it does not reason about who owns an order, whether a stored value will be trusted later, or what a session token is made of, and the trainee who has only ever clicked "active scan" cannot tell the difference between a clean result and a blind spot.

By the end you will have dumped the customer table through a search box, walked into the admin panel two different ways, planted a payload that fires only when an administrator opens a report, read a file off the database host through a price field, pulled a live API key out of an exposed .git directory, uploaded a web shell through an anonymous FTP login and run it from a browser, and chained the small findings into the big one. Then you will write it up.

Standing Up the Lab

Widgetorium is one docker-compose stack: a PHP and Apache storefront, a seeded MySQL 8 backend that is never published to the host, and an intentionally misconfigured vsftpd whose anonymous upload directory is shared straight into the web root. Every published port binds to 127.0.0.1 only.

cd widgetorium
./setup.sh          # preflight, build images, generate the lab certs, plant the .git history
./start.sh          # bring it up; refuses to launch if any port would bind beyond loopback
./status.sh         # health check plus a loopback bind audit
./reset.sh          # wipe stateful bugs back to seed between cohorts

Each session assumes a fresh browser session and a clean cookie jar. There is no shared state between sessions except what you plant yourself: an injected product row, a stored review, an uploaded shell. Run ./reset.sh when you want the lab back to seed.

The Toolbox

This course teaches the old-school way first. Every finding is worked by hand, with a browser, curl, openssl, and a packet capture, before any scanner is pointed at it. That order is deliberate. A trainee who has dumped a table with a hand-built UNION, read a TLS handshake line by line, and forged a session cookie in twenty lines of Python understands what the automated tool is doing when it does the same thing in one click, and, more importantly, understands what it is not doing. The scanners come in during the second half of each session, to confirm and to speed up the boring parts, never as the first move.

By hand, first

ToolRole in this course
The browser + dev toolsWalk the app like a user, read every parameter, inspect the session cookie, craft and confirm XSS payloads, watch a downgrade happen.
curlThe workhorse. The auth bypass, the IDOR walk, the upload and its traversal, the API body, and every error-based injection are one-liners you type yourself.
openssl s_clientRead the certificate and the handshake directly: subject, SAN, dates, negotiated protocol and cipher. Understand the finding before a report summarises it for you.
an FTP client (ftp, lftp)Log in anonymously, walk out of the unjailed home directory, drop a file by hand.
tcpdump / WiresharkCapture the cleartext FTP login on loopback and read the credentials off the wire yourself.
Python + requestsAbout twenty lines to predict and ride a session token. Not a tool problem, a scripting one, and worth doing from scratch.
git (plain)Once the .git directory is pulled, git log -p is all you need to find the secret in history.

Automation, second

ToolRole in this course
OWASP ZAPDiscovery sweep once you know the site by hand. Spider, AJAX spider, passive and active scan, and the Automation Framework plan in docs/zap/. Its value is coverage and speed, not insight.
sqlmapAfter you have exploited an injection point manually, hand it the same parameter and watch it enumerate systematically. Teaches what --level and --risk actually change.
testssl.sh (or sslyze)The full certificate and cipher report, once you can already read the same findings out of openssl s_client by hand.
gobuster / ffufDirectory and content brute-forcing. Finds the /admin/.git/ path and the FTP-uploaded shell faster than guessing.
git-dumperReconstructs the exposed .git working tree and history from HTTP so plain git can take over.
nmapService and version detection against the FTP box (-sV -sC -p21).
NiktoFast web-server misconfiguration sweep, a cross-check against ZAP's active scan.
hydraCredential brute-forcing against the FTP service account, once you have already guessed ftpuser:ftpuser by hand.
hashcatCrack the unsalted MD5 password hashes pulled from the users table.

The instructor edition of the scenario guide, docs/scenarios.md in the lab repo, maps every one of the nineteen findings to the tool that confirms it and the fix that closes it. Trainees work from docs/scenarios-trainee.md, the same document with the fix removed.
