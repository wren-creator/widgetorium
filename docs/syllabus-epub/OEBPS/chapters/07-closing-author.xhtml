About the Author

Britley Hoff is a Master Electrician, combat veteran, and systems architect who has spent over two decades mastering the invisible infrastructure that powers the modern world. Her journey with the mainframe began not in a lecture hall, but through the grit of self-directed research and a deep-seated obsession with how systems, both electrical and digital, hold up under pressure.

From early contributions to the openMosix cluster initiative and Slackware Linux, to managing zLinux environments at scale, Britley has always been drawn to Big Iron. To her, the mainframe was never a legacy burden, it was the ultimate engineering feat, a platform built for the kind of absolute reliability that mission-critical environments actually demand.

Britley lives in South Carolina, where she splits her time between architecting AI-native transaction systems, security research on the platforms everyone assumes are too old to matter, and running a fresh-foods hobby farm. She believes the systems that run the enterprise will only stay trustworthy if the people responsible for them have somewhere safe to break things first, and learn how they actually fail.

A Closing Note

This syllabus started from the same complaint the mainframe series did: nobody gets to practice on a real target before they need to already know one. Widgetorium exists to close that gap for the web layer. It is a boring shop with nineteen deliberate holes in it, running on your own machine, so a trainee can dump a customer table, upload a shell, and read a file off a database host without a single production system anywhere near the blast radius.

If you finished all six sessions, you have run every category a web assessment covers: injection, broken access control, cross-site scripting, unsafe file handling, weak session management, information disclosure, transport security, and a service pivot that ends in code execution. You have seen where ZAP earns its keep and where it goes quiet, and you have chained the quiet findings into the loud one. That is not a complete offensive-security education, nobody gets one of those in six sessions, but it is a real foundation, built on payloads that actually fired, not payloads copied from a slide.

Use Widgetorium only where you are meant to: on your own machine, in a lab you control, in a classroom or range where you have permission, under written rules of engagement for authorised training. It ships a live web shell path and crackable credentials by design. Keep it on loopback, keep the host off any network that matters, and never point the techniques in this book at a system you do not own or have explicit written authorisation to test.

The lab keeps growing. If you find a gap, a bug class that should be in here and isn't, an exploit path this book did not call out, a fix that does not hold up, write it down and build it next. That is how this course started: a handful of missing pieces in a lab that already worked.
