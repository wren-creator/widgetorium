Session 1: Orientation and Mapping by Hand

Goal for this session: get the lab running, then map the whole application yourself, with a browser and curl, before any scanner touches it. Only at the end do you run ZAP once, as a baseline, and the exercise there is to see how little it adds to a map you already built by hand. Do not try to exploit anything yet.

1.1 Confirm the Lab Is Contained

Before you point anything sharper than a browser at this, prove to yourself it cannot reach past your machine.

./status.sh                                   # runs the bind audit, exits non-zero on any 0.0.0.0
docker compose ps --format '{{.Name}}\t{{.Ports}}'   # every mapping must read 127.0.0.1:
nmap -Pn -p 8080,8443,21 <this-host-LAN-IP>    # from another box: all filtered or closed

start.sh already refuses to launch a configuration that would bind beyond loopback, and status.sh re-checks the running containers. Run the external nmap once anyway. Proving your lab is contained, every time, is the same reflex you use on a client engagement to prove your test traffic stayed in scope. Build it now.

1.2 Walk the Store Like a Customer

Open http://127.0.0.1:8080 and behave like a shopper. Browse the catalogue. Open a product. Search for "bolt". Register an account, log in, look at your order history. Log in again as admin / Widgetorium2024! and notice the extra "Admin" link in the header. Then open the HTTPS side, https://127.0.0.1:8443, and read the certificate warning your browser gives you instead of clicking past it.

1.3 Map Every Endpoint by Hand

Now go through the site again with intent and write down, on paper or in a flat file, every request the app makes. View source. Read the forms. Note the method, the path, and every parameter:

GET  /search.php?q=            reflected on the page
GET  /product.php?id=
GET  /orders.php?id=           and the /order.php alias
POST /login.php               username, password
POST /register.php
POST /review.php              product_id, author, body
POST /upload.php              multipart: image, optional filename
POST /api/update_item.php     JSON: id, price, qty
     /admin/                  index, products, inventory_report, config
     /admin/.git/             does this respond?

Confirm each one with curl -i so you have seen the raw response, the headers, the status, the body, not just the rendered page:

curl -sI http://127.0.0.1:8080/                       # Server, X-Powered-By, no HSTS on the 8443 side
curl -s  "http://127.0.0.1:8080/search.php?q=bolt"    # how does the term come back?
curl -s  -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8080/admin/.git/config

By the end of this step you have a complete map of the attack surface that you built, not one a tool handed you. Every later session works from this map.

1.4 Read the Transport by Hand

Before testssl.sh does it for you in Session 3, look at the certificate and the handshake yourself:

openssl s_client -connect 127.0.0.1:8443 -servername widgetorium.local </dev/null 2>&1 \
  | openssl x509 -noout -subject -issuer -dates -ext subjectAltName
curl -ksI https://127.0.0.1:8443/ | grep -i strict-transport-security   # nothing comes back

You should be able to say, out loud, three things that are wrong with this before you have run a single scanner: the name does not match, it is self-signed, and there is no HSTS.

1.5 Now Run ZAP, Once, as a Baseline

Proxy your browser through ZAP, browse the store again so the site tree is seeded with authenticated traffic, then run the spider, the AJAX spider, and let the passive scanner drain. The lab ships an Automation Framework plan that does the sweep:

docs/zap/run-zap.sh          # spider + AJAX spider + passive + active scan
                             # report lands at docs/zap/out/report.html

Read docs/zap/widgetorium-zap-plan.yaml first so you know what it is doing. When the report is ready, do not read it top to bottom. Instead, put it next to your hand-built map and answer two questions:

  • What did ZAP find that is not on my map? (Usually very little. The missing HSTS header, the self-signed cert, the reflected XSS, the SQL injection on search, the verbose error, all things you can also see by hand.)
  • What is on my map that ZAP said nothing about? (The second-order injection, the IDOR on order history, the exposed .git directory, the predictable session token, and the entire FTP box.)

That second list is the rest of the course.

1.6 What You Should Notice

You mapped this application in half an hour with a browser and curl, and the scanner, run afterward, mostly confirmed what you already had. The findings that matter most, the ones about who owns an order, whether a stored value gets trusted later, what a session token is made of, were never going to come from a tool that only connects requests to responses. Old-school first is not a style choice. It is the only way to know where the automated tool stopped seeing.
